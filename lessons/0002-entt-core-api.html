第2课：EnTT 核心 API

EnTT-Pacman 课程 · 第一部分：地基

Registry — 整个 ECS 世界的「数据库」

在第1课中我们知道了 Entity、Component、System 是什么。现在来看看它们如何在代码中运转。 一切从一个对象开始： 

#include <entt/entity/registry.hpp>

entt::registry reg;   // 整个 ECS 世界就装在这个对象里

类比： reg 就像一个 Excel 表格。每一行是一个 Entity（行号），每一列是一种 Component。某个格子里有值，就说明那个实体拥有那个组件。

在 EnTT-Pacman 中，reg 是 Game 类的成员变量：

// src/core/game.hpp
class Game {
private:
  entt::registry reg;   // ← ECS 世界的拥有者
  MazeState maze;
  int dots = 0;
  // ...
};
关键约定：几乎所有的 EnTT 函数都接受 entt::registry & 作为第一个参数。系统函数通过这个引用访问整个 ECS 世界。

API 1：create — 创建实体

创建一个实体就是让 registry 分配一个新的行号：

const entt::entity e = reg.create();    // e 可能等于 0, 1, 2, ...
// 此时 e 是一个「空实体」，没有任何组件
API作用返回值
reg.create()创建一个空实体entt::entity（本质是 uint32_t 或 uint64_t）
C++ 提示：entt::entity 只是一个整数的类型别名。你可以在调试器中把它打印出来——它就是一个数字。如果 EnTT 配置为 32 位模式，一个 registry 最多可以有约 40 亿个实体。

API 2：emplace — 给实体挂组件

创建实体后，它还是空的。用 emplace 给它挂上组件：

// 给实体 e 挂上一个 Position 组件，初始值为 {5, 3}
reg.emplace<Position>(e, 5, 3);

// 如果 Position 定义是 struct Position { int x, y; };
// 那么 emplace<Position>(e, 5, 3) 会用 Position{5, 3} 来构造

// 给实体 e 挂上一个空的 Player 标签
reg.emplace<Player>(e);    // Player 是空结构体，不需要参数

看看项目中的真实用法——src/core/factories.cpp：

entt::entity makePlayer(entt::registry ®) {
  const entt::entity e = reg.create();          // 1. 创建空实体

  reg.emplace<Player>(e);                        // 2. Player 标签
  reg.emplace<DesiredDir>(e, playerSpawnDir);     // 3. 期望方向（Dir 枚举值）
  reg.emplace<ActualDir>(e, playerSpawnDir);       // 4. 实际方向
  reg.emplace<Position>(e, playerSpawnPos);        // 5. 出生位置（Pos 结构体）
  reg.emplace<PlayerSprite>(e, animera::SpriteID::pacman_beg_); // 6. 精灵 ID

  return e;   // 返回实体 ID 供后续使用
}
重要：emplace 如果发现实体 已经有 同类型组件，会覆盖它。这不是错误，也不会警告——旧数据直接替换。这也意味着你可以用它来修改组件值。

API 3：get — 读取实体的组件

已经挂上的组件，通过 get 读出来：

// 获取实体 e 的 Position 组件引用
Position &pos = reg.get<Position>(e);
pos.x = 10;    // 直接修改，EnTT 内部会感知到这个变化

// 也可以读标签组件（虽然没什么可读的）
const Player &player = reg.get<Player>(e);

在项目中随处可见：

// src/sys/set_target.cpp — Blinky 的追逐目标 = 玩家的位置
void setBlinkyChaseTarget(entt::registry ®) {
  auto view = reg.view<Target, ChaseMode, BlinkyChaseTarget>();
  for (const entt::entity e : view) {
    const entt::entity player = view.get<BlinkyChaseTarget>(e).player;
    view.get<Target>(e).p = reg.get<Position>(player).p;   // ← get!
  }
}
C++ 提示：reg.get<T>(e) 返回的是 引用（T&）。你直接修改它，EnTT 内部存储就会被修改。这是 EnTT 的零开销设计——没有拷贝，没有事件通知，直接操作内存。

API 4：try_get — 安全地读取组件

get 有一个危险：如果实体没有这个组件，行为是未定义的（Release 模式下可能崩溃或读到垃圾数据）。当你不确定实体是否有某个组件时，用 try_get：

// try_get 返回指针：有组件 → 返回指针，没有 → 返回 nullptr
if (const Position *pos = reg.try_get<Position>(e)) {
  // 实体有 Position 组件
  std::cout << pos->x << '\n';
} else {
  // 实体没有 Position 组件
}
API行为何时使用
reg.get<T>(e)返回引用，没有则未定义行为你确定实体有这个组件时（如在 view 迭代中）
reg.try_get<T>(e)返回指针，没有则 nullptr你不确定实体是否有这个组件时

API 5：remove — 移除实体的组件

运行时改变实体「身份」的核心手段：

reg.remove<ChaseMode>(e);       // 移除追逐模式标签
reg.emplace<ScaredMode>(e);     // 换成恐惧模式标签
// 现在这个幽灵从"追逐状态"变成了"恐惧状态"

在 EnTT-Pacman 中，幽灵模式切换就是通过 remove + emplace 实现的：

// src/sys/change_ghost_mode.cpp（简化）
void ghostChase(entt::registry ®) {
  auto view = reg.view<ScatterMode>();
  for (const entt::entity e : view) {
    reg.remove<ScatterMode>(e);     // 移除 ScatterMode
    reg.emplace<ChaseMode>(e);      // 挂上 ChaseMode
  }
}
这就是 ECS 的「运行时改身份」！ 不需要修改类、不需要改继承树、不需要 new/delete。幽灵切换模式 = 换一个标签组件。

API 6：destroy — 销毁实体

销毁实体会同时移除它挂载的所有组件：

reg.destroy(e);
// 实体 e 不再存在，其所有组件内存被回收

在 Pacman 中很少用到这个——玩家和幽灵不会被销毁。但在其他游戏中（子弹、敌人死亡），这个 API 很重要。

API 7：all_of / any_of — 检查组件是否存在

// 检查实体 e 是否同时拥有 Position 和 Player 组件
if (reg.all_of<Position, Player>(e)) { ... }

// 检查实体 e 是否拥有 ScaredMode 或 ChaseMode（至少一个）
if (reg.any_of<ScaredMode, ChaseMode>(e)) { ... }

这在你需要做条件判断时很有用——比如「如果幽灵处于恐惧模式，就不能吃玩家」。

API 速查总表

操作API说明
创建实体auto e = reg.create()返回一个空实体 ID
挂载/覆盖组件reg.emplace<T>(e, args...)如果已有同类型组件则覆盖
读取组件（引用）reg.get<T>(e)没有则未定义行为 ⚠️
安全读取（指针）reg.try_get<T>(e)没有则返回 nullptr
移除组件reg.remove<T>(e)只移除指定类型
销毁实体reg.destroy(e)移除实体及所有组件
检查存在（ALL）reg.all_of<T...>(e)全部拥有 → true
检查存在（ANY）reg.any_of<T...>(e)至少一个 → true

测验答案
  1. 位置是 {10, 20}。第二次 emplace 覆盖了第一次的值。emplace 总是用新值替换旧值。
  2. 因为 get 没有做任何检查——它假设组件一定存在。如果不存在，在 Release 模式下可能访问到野内存，导致崩溃或静默的数据损坏。在 Debug 模式下 EnTT 通常会触发 assert。
  3. reg.remove<ScatterMode>(e); 然后 reg.emplace<ChaseMode>(e);。两步操作：先移除旧模式标签，再挂上新模式标签。
