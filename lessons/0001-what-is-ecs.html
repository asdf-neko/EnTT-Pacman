第1课：ECS 是什么？

EnTT-Pacman 课程 · 第一部分：地基

从一个问题开始

假设你要写一个游戏，里面有玩家（Player）和幽灵（Ghost）。 用传统的面向对象（OOP）方式，你很可能会这样设计： 

// 传统 OOP 继承树
class GameObject {           // 所有东西的基类
  int x, y;                  // 位置
  virtual void update() = 0; // 每帧更新
};

class Movable : public GameObject {
  int dx, dy;                // 移动方向
  virtual void move() { ... }
};

class Renderable : public GameObject {
  Sprite* sprite;            // 贴图
  virtual void draw() { ... }
};

class Player : public Movable, public Renderable {
  int score;                 // 分数
  void update() override { move(); draw(); }
};

class Ghost : public Movable, public Renderable {
  AI* brain;                 // AI 逻辑
  void update() override { brain->think(); move(); draw(); }
};
问题来了：如果以后想加一个「不会动的装饰物」，或者想让幽灵暂时不渲染，或者让玩家拥有幽灵的 AI 能力——继承树就会越来越扭曲，最终变成「钻石问题」和「上帝基类」的地狱。

这就是 ECS 要解决的核心问题：继承描述的是「是什么」，而游戏真正关心的是「有什么」。

ECS 的答案：把数据和逻辑拆开

ECS 把游戏对象拆成三个概念：

概念 是什么 EnTT-Pacman 中的例子
Entity（实体） 一个 ID 编号，没有数据也没有行为 玩家 entity = 42，幽灵 entity = 99
Component（组件） 纯数据，挂载到 Entity 上 Position{ x: 5, y: 3 }、Player{}、Ghost{}
System（系统） 纯逻辑，操作拥有特定组件的实体 movement() 系统搬动所有有 Position 的实体

关键洞察：Entity 只是一个数字。它的「身份」完全由它挂了哪些 Component来决定。

看看真实代码：EnTT-Pacman 的组件

打开项目的 src/comp/ 目录，你会看到这些文件： 

src/comp/
├── player.hpp        // struct Player {}        ← 只有名字，没有数据！
├── ghost.hpp         // struct Ghost {}         ← 也是空的！
├── position.hpp      // struct Position { Pos p; }
├── dir.hpp           // struct DesiredDir { Dir d; }
│                     // struct ActualDir { Dir d; }
├── target.hpp        // struct Target { Pos p; }
├── ghost_mode.hpp    // struct ChaseMode {} / ScatterMode {} / ScaredMode { int timer; }
├── chase_target.hpp  // struct BlinkyChaseTarget { entity player; }
├── sprite.hpp        // struct PlayerSprite { SpriteID id; }
└── ...
注意两类组件：
  • Tag Component（标签组件）：Player{}、Ghost{}、ChaseMode{} —— 空结构体，只用来「标记」实体是什么状态。
  • Data Component（数据组件）：Position{}、Target{}、ScaredMode{ timer } —— 持有实际数据。

玩家 vs 幽灵：挂在同一个实体上的组件完全不同

在 src/core/factories.cpp 中，创建玩家和幽灵的方式清楚地展示了 ECS 的思想：

// 创建玩家 —— 挂 5 个组件
entt::entity makePlayer(entt::registry ®) {
  const entt::entity e = reg.create();               // 1. 创建一个空实体（只是一个整数）
  reg.emplace<Player>(e);                            // 2. 贴上 "我是玩家" 标签
  reg.emplace<DesiredDir>(e, playerSpawnDir);         // 3. 期望方向
  reg.emplace<ActualDir>(e, playerSpawnDir);          // 4. 实际方向
  reg.emplace<Position>(e, playerSpawnPos);           // 5. 出生位置
  reg.emplace<PlayerSprite>(e, animera::SpriteID::pacman_beg_); // 6. 精灵图
  return e;
}

// 创建幽灵 —— 挂不同的组件！
entt::entity makeGhost(...) {
  const entt::entity e = reg.create();
  reg.emplace<Position>(e, home);      // ✓ 有位置（和玩家一样）
  reg.emplace<HomePosition>(e, ...);   // ✨ 有「家」的位置（玩家没有）
  reg.emplace<LeaveHouse>(e);          // ✨ 有「离开鬼屋」门票（玩家没有）
  reg.emplace<ScatterMode>(e);         // ✨ 初始是散射模式（玩家没有）
  reg.emplace<Target>(e);             // ✨ 有追踪目标（玩家没有）
  reg.emplace<Ghost>(e);              // ✨ 贴上 "我是幽灵" 标签
  return e;
}
看到了吗？ 玩家和幽灵共享 Position 和方向组件（因为它们都需要移动），但幽灵额外拥有 Target（追踪目标）、HomePosition（家）、Ghost（标签）等组件。

如果将来想让幽灵也能吃豆子？给幽灵加上 Player 标签就行。想让玩家能飞？加个 Flying 组件就行。不需要改继承树，只需要增减组件。

系统如何工作？

组件只是数据，真正干活的是 System（系统）。系统是一段纯函数，它说：「给我所有同时拥有 Position 和 ActualDir 的实体，我来移动它们」。 

// src/sys/movement.cpp
void movement(entt::registry ®) {
  // view = "给我所有同时有 Position 和 ActualDir 的实体"
  auto view = reg.view<Position, ActualDir>();
  for (const entt::entity e : view) {
    Pos &pos = view.get<Position>(e).p;
    const Dir dir = view.get<ActualDir>(e).d;
    pos += toPos(dir);   // 把位置往方向偏移一格
  }
}

这个系统不关心实体是玩家还是幽灵。它只关心「你有没有 Position 和 ActualDir」。如果你有，你就被移动。这就是 ECS 的核心威力：逻辑和身份完全解耦。

ECS vs OOP 对比总结

传统 OOP ECS
数据存储 分散在继承链的各个类中 集中在 Component 中，按类型连续存储
行为定义 绑定在类的方法上 独立的 System 函数
添加新能力 需要修改继承树 添加新组件 + 新系统
运行时改身份 几乎不可能 增删组件即可
缓存友好性 差（对象分散在内存中） 好（同类型组件连续存储）

测验答案
  1. Player{} 是标签组件（Tag Component）。它自己不存数据，但让系统能通过 view<Player>() 筛选出属于玩家的实体。比如 playerInput() 系统只处理有 Player 标签的实体。
  2. 修改 ScaredMode 组件，或新增一个 Speed 组件。在 ECS 中，你会添加数据到已有的组件（或创建新组件），然后让 movement 系统读取它。
  3. 不需要。 movement() 只查看 Position 和 ActualDir 组件。任何同时拥有这两个组件的实体都会被移动——无论是玩家、幽灵，还是将来添加的任何东西。
