# 0001-ecs-core-concepts

## Date
2026-06-27

## Lesson
第1课：ECS 是什么？

## Key Insights

1. **ECS 解决的核心问题**：传统 OOP 继承树用「是什么」组织代码，但游戏真正需要的是「有什么」。继承导致代码僵化，ECS 通过组合解决。

2. **Entity = 一个整数**：实体本身没有数据和行为，只是一个 ID，类似于数据库中的主键。

3. **Component = 纯数据**：每个组件是一个 struct，不包含任何方法。分为两种：
   - Tag Component（如 `Player{}`）：空结构体，纯标记
   - Data Component（如 `Position{Pos p}`）：持有数据

4. **System = 纯逻辑**：系统是独立函数，操作拥有特定组件组合的实体。系统不关心实体的「身份」，只关心「有没有需要的组件」。

5. **组合优于继承**：通过给实体挂不同的组件，可以实现灵活的行为组合，不需要修改任何继承树。
